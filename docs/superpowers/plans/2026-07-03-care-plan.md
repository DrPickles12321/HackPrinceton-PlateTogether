# Care Plan Features Implementation Plan

> **For agentic workers:** Executed inline (executing-plans), task-by-task with tests.

**Goal:** Three clinician-approved features: (1) pre/post-meal distress ratings, (2) clinician-assigned challenge foods, (3) multi-week progress trends.

**Architecture:** All data lives under the existing `users/{uid}` RTDB tree. Distress rides inside `mealLogs/{date}/{meal}` (same write rule as statuses); assigned challenges get a new `assignedChallenges` node (clinician-writable, like `sos`); trends are pure client-side computation over `mealStatuses`. Every UI lands on desktop + mobile per the standing rule.

**Tech stack:** React 18 + Vite, Firebase RTDB, Vitest.

---

## Task 1: Trends lib (`computeWeeklyTrend`)

**Files:** Create `src/lib/trends.js`, `src/lib/trends.test.js`

- `computeWeeklyTrend({ mealStatuses, weeks = 6, base = new Date() })` → oldest→newest
  `[{ startIso, label, logged, okay, okayPct }]`, built on `getWeekDates(offset, base)`
  (base injectable for tests). `label` = short "Jun 29".
- Tests: multi-week counts, zero weeks, okayPct rounding, oldest-first ordering.

## Task 2: TrendChart + Insights + Clinician

**Files:** Create `src/components/TrendChart.jsx`; modify `src/pages/StatsView.jsx`, `src/pages/ClinicianView.jsx`

- SVG chart: soft bars = meals logged (scale 0–28), coral line + dots = okay %,
  week labels beneath, `compact` prop for mobile. Empty state when no week has data.
- StatsView: "Progress Over Time" card after Daily Rhythm (mobile + desktop branches).
- ClinicianView: same card in the viewed-patient section (context `mealStatuses` is
  already the patient's when viewing).

## Task 3: Distress data layer

**Files:** Modify `src/contexts/FirebaseDataContext.jsx`

- `deriveMealDistress(fbMealData)` → `{ [date]: { [meal]: { pre, post } } }`.
- Expose `mealDistress` (active = patient's when clinician viewing).
- `setMealDistress(date, mealType, patch)` → `update()` on
  `users/{uid}/mealLogs/{date}/{mealType}/distress` (merges `{pre}` or `{post}`).
  No rules change needed — `mealLogs` is already own-writable, patient-readable.

## Task 4: Distress UI (parent) + stats

**Files:** Create `src/components/DistressScale.jsx`; modify `src/pages/DailyView.jsx`,
`src/lib/weekSummary.js`, `src/lib/weekSummary.test.js`, `src/pages/StatsView.jsx`, `src/lib/weekFacts.js`

- `DistressScale`: "How upset was it? Before / After" — two rows of 5 tap-dots
  (1 calm → 5 very hard), tap again to clear. Renders under the status buttons in
  desktop `MealCard` and expanded `MobileMealCard`, only when a non-skip status is set.
- `computeDistressSummary(mealDistress, isoDates)` → `{ count, avgPre, avgPost }` + tests.
- StatsView: "Distress check-ins" mini-card (Before avg → After avg with ↓/↑).
- weekFacts: include distress summary so the chatbot can reference it.

## Task 5: Assigned challenges — data + rules

**Files:** Modify `database.rules.json`, `src/contexts/FirebaseDataContext.jsx`; deploy rules

- Rule: `"assignedChallenges": { ".write": "auth.uid === $uid || root.child('users/' + auth.uid + '/patients/' + $uid).exists()" }`
- Context: own + patient listeners → `assignedChallenges` (active view);
  `addAssignedChallenge(name)` / `removeAssignedChallenge(id)` writing to
  `viewingPatientUid || uid`. Record: `{ name, createdAt }`.
- `firebase deploy --only database`.

## Task 6: Assigned challenges — UI

**Files:** Create `src/components/ChallengeAssigner.jsx`; modify `src/pages/ClinicianView.jsx`,
`src/components/FoodSidebar.jsx`, `src/components/AddFoodSheet.jsx`

- Clinician: "Challenge Foods" card (input + Add, list with ✕) near the supplements editor.
- Parent: `SuggestedFoods` gains `assignedChallenges` prop → pinned "🎯 From your clinician"
  section at top; one tap adds as `category: 'challenge'` (challenge ring picks it up
  automatically). Both FoodSidebar (desktop) and AddFoodSheet (mobile) pass it.
